# Graph tools and Neo4j MCP

The harness has two graph interfaces. `GraphTools` makes four bounded reads with the official Neo4j Python driver. `Neo4jMCPTools` connects to the [official Neo4j MCP server](https://neo4j.com/docs/mcp/current/) using the [official Python MCP SDK](https://py.sdk.modelcontextprotocol.io/v1/). The MCP server supplies `get-schema` and `read-cypher`; the adapter only changes their agent-facing names to `neo4j_get_schema` and `neo4j_read_cypher`. The two interfaces can be registered separately or together.

## Dependencies and Colab service

- Python package requirements: `neo4j>=5.26,<7`, `mcp>=1.30,<2`; install the [Neo4j MCP server](https://neo4j.com/docs/mcp/current/installation/) as `neo4j-mcp-server==1.6.1`. Its verified PyPI console entry point is `neo4j-mcp-server`, which is the adapter default. The manually installed official binary is `neo4j-mcp`; pass `command="neo4j-mcp"` explicitly if using that distribution. This server package has Linux x86-64 wheels. The driver adapter was tested with driver 6.4.1 against the existing Neo4j 5.26 service; it has not been tested with driver 5.x. The SDK 1.x is the supported line for this adapter; 2.x changes the client API.
- Restore the bundle into Neo4j **5.26.32** with **APOC installed** before starting the MCP server. The [server checks APOC, including its `meta` component, and connectivity during the handshake](https://neo4j.com/docs/mcp/current/requirement-checks/). Use the matching Neo4j 5.26 APOC distribution; verify `SHOW PROCEDURES YIELD name WHERE name STARTS WITH 'apoc.meta' RETURN name` returns entries. The bundle's restore script owns schema creation and data writes. Do not let an agent create constraints or import data.
- The Colab runtime's Neo4j service and official server run locally. Set `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, `NEO4J_DATABASE` for the driver. The MCP adapter maps these to `NEO4J_MCP_*` unless the latter are explicitly set. Keep secrets in environment variables; they are passed to the child process environment, never command-line arguments or logs.
- The MCP adapter forces `NEO4J_MCP_READ_ONLY=true`, `NEO4J_MCP_TOOLS=get-schema,read-cypher`, and stdio. [Official read-only classification](https://neo4j.com/docs/mcp/current/tools/) rejects writes, schema/admin operations, and `PROFILE`. Restrict the Neo4j account to read privileges too. MCP `read-cypher` can read any data that account can access, so use the dedicated restored Colab database and avoid putting unrelated data there.
- Adapter CLI arguments cannot override the connection, transport, read-only or tool-list settings; the official server gives CLI flags precedence over environment values, so these flags are rejected before process launch.

## Namespace and graph meaning

Construct `GraphTools(driver, run_id=<restored run ID>, database=<restored database>)` from runtime configuration. The actual bundle may carry `graph:a9a3ad6409e5409baa97f84394656936`, but the class never hardcodes it. Every custom read starts with `KGNode {run_id:$run_id,node_id:$node_id}` or an `UNWIND` of at most 20 IDs into the same composite identity. The publisher creates the `(run_id,node_id)` constraint. The query layer never creates indexes.

The published labels are `Paper`, `PaperVersion`, `Source`, `SourceItem`, `Contribution`, `ResearchProblem`, `Method`, `Benchmark`, and `ResearchArea`. Edges are `HAS_VERSION`, `HAS_SOURCE`, `HAS_ITEM`, `RESOLVES_TO`, and `MEMBER_OF`. A source mention reaches a reviewed canonical entity through `SourceItem-[:RESOLVES_TO]->entity`; a contribution is attached to `Source` with `HAS_ITEM`; a ResearchProblem can be a `MEMBER_OF` a ResearchArea. `find_shared_papers` means source mentions for every requested entity occur under the same paper. It is a co-occurrence result, not a claim that a method solves a problem or was evaluated on a benchmark. `get_evidence` returns source JSON, mention roles, and Paper→Version→Source lineage; it does not promote a mention into an established scientific assertion.

`get_node`, `expand_neighbors`, `find_shared_papers`, and `get_evidence` accept only bounded inputs. Expansion is one hop, relation names are validated against a fixed allowlist, and all other values are parameterized. Limits are 1–50 records. The official driver's `unit_of_work(timeout=30)` bounds each read transaction. Explicit node projections omit potentially large `PaperVersion.text`; source JSON is capped at 4,000 characters in the database projection. A truncated source JSON string is only a locator excerpt. Read the original source outside this tool if more context is needed.

## Lifecycle and result shape

Use one `async with Neo4jMCPTools(...) as tools` per harness run, then register `tools.tools` and route calls to `await tools.call(name,args)`. Initialization and tool discovery occur once; the context manager closes the session and child process. The MCP result retains `is_error`, typed `content`, and `structured_content`. The harness must relay `is_error` as an error, rather than turning server failure into an answer. The custom driver's `.tools`/`.call` contract is the same, but its read calls return their rows directly.

The official server's `get-schema` is database-wide. It does not filter on run ID. Use the dedicated restored database. The custom query layer confines reads to the configured run ID.
